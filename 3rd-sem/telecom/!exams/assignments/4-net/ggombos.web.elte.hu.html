NetCopy GmbH

Erstellen Sie eine Netcopy-Client/Server-Anwendung, mit der Sie eine Datei übertragen und die übertragenen Daten mit einer CRC- oder MD5-Prüfsumme überprüfen können! Während der Aufgabe drei eine Komponente/ein Programm ist vorzubereiten:

1. Checksum Server: (Dateiidentifikation, Prüfsumme Länge, Prüfsumme, Ablauf (in s)) ermöglicht es Ihnen, Vieren zu speichern und abzufragen. Einzelheiten zum Protokoll finden Sie unten.
2. Netcopy-Client: sendet eine Datei, die in einem Befehlszeilenargument angegeben ist, an den Server. Während/am Ende der Übertragung berechnet es eine md5-Prüfsumme für die Datei und lädt sie dann zusammen mit einer Datei-ID auf den Checksum-Server hoch. Das Ablaufdatum beträgt 60 Sekunden. Eine Dateikennung ist eine ganze Zahl, die auch in einem Befehlszeilenargument eingegeben werden muss.
3. Netcopy Server: Warten auf einen Kunden zum Beitritt. Nach der Verbindung erhält es die übertragenen Bytes und platziert sie in der im Befehlszeilenargument angegebenen Datei. Am Ende ruft es die md5 Prüfsumme für die Datei-ID vom Checksum-Server ab und überprüft die Richtigkeit der übertragenen Datei, deren Ergebnis auch auf stdoutput geschrieben wird. Die Datei-ID muss auch ein Befehlszeilenargument sein.

Checksum Server

  • Nachricht einfügen
    • Format: Text
    • Struktur: ON|< Datei darauf. >|< Gültigkeit in Sekunden >|< Prüfsumme Länge in Byte Zählung >|< checksum bytes >>
    • Das „|“ Trennzeichen
    • Beispiel: BE|1237671|60|12|abcdefabdef
      • In diesem Fall: die Datei: 1237671, 60sec ist die Gültigkeitsdauer, 12 Byte der Prüfsumme, abcdefabcdef ist die Prüfsumme selbst
      • Antwort Nachricht: OK
  • Nimmt die Botschaft heraus
    • Format: Text
    • Struktur: KI|< Datei darauf. >
    • Das „|“ Trennzeichen
    • Beispiel: OFF|1237671
      • Das heißt, bitte Prüfsumme für die Dateikennung 1237671
      • Antwortnachricht: < Prüfsummenlänge in Byte-Anzahl >|< Checksummen-Bytes >
      • Beispiel: 12|abcdabcdef
    • Wenn es keine Prüfsumme gibt, sendet sie: 0|
  • Lauf
    • python3 checksum_srv.py < ip > < port>
      • < ip> - z.B. localhost für Server-Adressbindung
      • < port > - wird auf diesem Port verfügbar sein
    • Der Server läuft in einem unendlichen Zyklus und kann mehrere Clients gleichzeitig bedienen. Kommunikation ist TCP, sie verarbeitet nur die oben genannten Nachrichten.
    • Post-Expiry-Prüfsummen werden gelöscht, aber es reicht aus, nur auf die nächste Anfrage zu überprüfen.

NetCopy-Client

  • Operation:
    • Es ist mit dem Server verbunden, deren Adresse und Port Sie in einem Befehlszeilenargument erhalten.
    • Kontinuierliche Übertragung von Dateibytes auf den Server.
    • Kommunizieren Sie mit dem Checksum-Server, wie dort beschrieben.
    • Nachdem die Datei übertragen und die Prüfsumme platziert wurde, trennt sie die Verbindung und das Terminal.
  • Laufen:
    • python3 netcopy_cli.py < srv_ip > < srv_port > < chsum_srv_ip > < chsum_srv_port > < Datei mit Pfad > < Dateinamenpfad >
    • < Datei auf >: integer
    • < srv_ip > < srv_port >: Verfügbarkeit des netcopy-Servers
    • < chsum_srv_ip > < chsum_srv_port >: Verfügbarkeit des Checksum-Servers

NetCopy Server GmbH

  • Operation:
    • Binden Sie den Socket an die im Befehlszeilenargument angegebene Adresse.
    • Er wartet auf einen Kunden.
    • Wenn Sie es akzeptiert haben, erhält es die Bytes der Datei kontinuierlich und schreibt sie in die im Befehlsargument angegebene Datei.
    • Wenn Sie ein Dateiendsignal lesen, schließt es die Verbindung und überprüft dann die Datei mit dem Checksum-Server.
    • Kommunizieren Sie mit dem Checksum-Server, wie dort beschrieben.
    • Im Falle eines Fehlers muss es auf dem Stdout geschrieben sein: CSUM CORRUPTED
    • Bei korrekter Übermittlung muss sie auf das Stdout geschrieben werden: CSUM OK
    • Datei empfangen und überprüfen nach dem Terminal des Programms.
  • Laufen:
    • python3 netcopy_srv.py < srv_ip > < srv_port > < chsum_srv_ip > < chsum_srv_port > < Datei mit Pfad > < Dateiname mit Pfad >
      • < Datei auf >: integer ua. wie im Client – so rufen Sie die Prüfsumme vom Server ab
      • < srv_ip > < srv_port >: Verfügbarkeit des Netcopy-Servers – muss bei Bindung erfolgen
      • < chsum_srv_ip > < chsum_srv_port >: Verfügbarkeit des Checksum-Servers
      • < Dateiname > : hier können Sie die Bytes schreiben, die Sie erhalten haben

Einreichung: Senden Sie das Programm auf dem TMS-System .zip Format, in welchem checksum_srv.py, eins netcopy_cli.py und eins netcopy_srv.py Enthalten sein!

NetCopyEn GmbH

Erstellen Sie eine netcopy client/server-Anwendung, die die aktivierte Übertragung einer Datei und die Validierung der übertragenen Daten mit einer CRC- oder MD5-Prüfsumme ist! Während der Aufgabe, dreiKomponenten/Programme müssen vorbereitet werden:

1. Checksum Server: Speicherdaten: (Dateikennung, Prüfsumme Länge, Prüfsumme, Ablauf (in Sekunden)). Details zum Protokoll finden Sie unten.
2. Netcopy-Client: Überträgt die in einem Befehlszeilenargument enthaltene Datei auf den Server. Während/am Ende der Übertragung berechnet sie eine Prüfsumme für die Datei und lädt sie dann mit der Datei-ID auf den Checksum-Server hoch. Die Ablaufzeit beträgt 60 Sekunden. Die Datei ist die Kennung einer Ganzzahl, die ebenfalls in einem Befehlsargument angegeben werden muss.
3. Netcopy Server: Wartet darauf, dass sich ein Client verbindet. Nach der Verbindung empfängt es die übertragenen Bytes und platziert sie in der Datei im Befehlszeilenargument. Am Ende ruft es die mit der Dateikennung verknüpften Prüfungen vom Checksum-Server ab und überprüft die Richtigkeit der übertragenen Datei, wodurch sie auch in die Standardausgabe geschrieben wird. Die Datei muss auch ein Befehlszeilenargument sein.

Checksum server

  • Insert message
    • Format: text
    • Structure: BE|< file id >|< validity in seconds >|< checksum length in bytes >|< checksum bytes >
    • The "|" is the delimiter character
    • Example: BE|1237671|60|12|abcdefabcdef
      • In this case: the file number: 1237671, the validity period is 60 seconds, the checksum is 12 bytes, the checksum itself is abcdefabcdef
      • Response message: OK
  • Take out message
    • Format: text
    • Structure: KI|< file id >
    • The "|" is the delimiter character
    • Example: KI|1237671
      • That is, we are asking for the checksum for file ID 1237671
      • Response message: < checksum length in bytes >| < checksum bytes >
      • Example: 12|abcdefabcdef
    • If there is no checksum, it sends: 0|
  • Run
    • python3 checksum_srv.py < ip > < port >
      • < ip > - e.g. localhost is the address of the server when binding
      • < port > - will be available on this port
    • The server runs in an endless cycle and can serve several clients at the same time. The communication is TCP, it only handles the above messages.
    • Post-expiration checksums are deleted, but it is enough if you only check them at the next request.

NetCopy Client

  • Operation:
    • Connects to the server, whose address and port you receive in command line arguments.
    • Sequential transfer of file bytes to the server.
    • It communicates with the Checksum server as described there.
    • After transferring the file and placing the checksum, disconnect and terminal.
  • Run:
    • python3 netcopy_cli.py < srv_ip > < srv_port > < chsum_srv_ip > < chsum_srv_port > < file id > < filename with path >
    • < file id >: integer
    • < srv_ip > < srv_port >: netcopy server address
    • < chsum_srv_ip > < chsum_srv_port >: Checksum server address

NetCopy Server

  • Operation:
    • Binds the socket to the address specified in the command line argument.
    • Waiting for a client.
    • If accepted, it accepts the bytes of the file sequentially and writes them to the file specified in the paragraph line argument.
    • When an end-of-file signal is read, it closes the connection and then checks the file with the Checksum server.
    • It communicates with the Checksum server as described there.
    • In the event of an error, the following should be written to stdout: CSUM CORRUPTED
    • If the transfer is correct, the following should be written to stdout: CSUM OK
    • After receiving and checking the file, the program is terminal.
  • Run:
    • python3 netcopy_srv.py < srv_ip > < srv_port > < chsum_srv_ip > < chsum_srv_port > < file id > < filename with path >
      • < file id >: integer same as for the client - based on this, it requests the checksum from the server
      • < srv_ip > < srv_port >: address of the netcopy server - required when binding
      • < chsum_srv_ip > < chsum_srv_port >: Checksum server address
      • < file name > : write the received bytes here

Einreichung: Senden Sie es an das TMS in .zip Format, enthält welche checksum_srv.py, die netcopy_cli.py und ein netcopy_srv.py Nur!
